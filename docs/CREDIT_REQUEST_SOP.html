Credit Request System

Standard Operating Procedure (SOP)

Overview

The Credit Request System is a three-part workflow that captures credit/complaint requests from customers through a form, validates and routes them through HubSpot, with data sourced from Business Central.

Part 1: Credit Request Form

Purpose: Collect customer-initiated credit requests and complaints

Form Structure

Section 1: Contact Information *Required

Field Type Mapped To
First Name Text Input HubSpot Contact: firstname
Last Name Text Input HubSpot Contact: lastname
Email Email Input HubSpot Contact: email
Phone Tel Input HubSpot Contact: phone

Section 2: Account Information *Required

Field Type Mapped To
Account # Text Input (ERP lookup) Company: erp_account_number, Ticket: account__
Business Name Text Input Ticket: company_name
Invoice Number Text Input Ticket: invoice

Section 3: Product Lines *Required (1-10 items)

Field Type Mapped To
Product Number Datalist (BC sourced) Item: item_no_
Product Description Text (auto-filled) Item: item_description
Production Code Text Input Item: julian_code
Quantity Number Input Item: quantity
Request Type Dropdown Item: request_type
Issue Classification Datalist Item: complaint_type
Notes Textarea Item: line_notes
Photos / Attachments File Upload (conditional) Item: photosdocumentation

Section 4: Additional Notes (Optional)

Field Type Mapped To
Reason / Notes Textarea Ticket: credit_summary

Form Dropdowns Explained

1. Product Number (Datalist Dropdown)

  • Type: Searchable autocomplete
  • Source: Business Central Items (via BC Items Proxy)
  • Behavior: User types product # or description, shows matching items
  • Display: Product # + Description as they type
  • Required: Yes
  • Maps to: Item: item_no_

2. Request Type (Standard Dropdown)

Options:

  • Credit — Customer requesting refund/credit
  • Complaint — Reporting quality/delivery issue

Required: Yes (one per product line)

Maps to: Item: request_type

⚠️ Critical Impact: Determines routing stage:

  • If ANY item = "Complaint" → Routes to CAPA stage
  • If all = "Credit" + Total Qty ≥ 10 → Routes to Verification stage
  • If all = "Credit" + Total Qty < 10 → Routes to Credit Decision stage

3. Issue Classification / Complaint Type (Datalist Dropdown)

Available Options:

  • Flavor
  • Size
  • Color
  • Mold
  • Damaged Packaging

Required: Yes

Maps to: Item: complaint_type

⚠️ Conditional Photo Requirement:

  • Photos REQUIRED for: Flavor, Size, Color, Mold, Damaged Packaging
  • Photo field becomes mandatory when these are selected
  • Form will not submit without photos for these classifications

Part 2: Credit Request – BC Items Proxy

Purpose: Provide Business Central item data to the form and sync item information

Data Flow

Business Central Database ↓ BC Items Proxy Workflow ↓ Transforms BC Item Data ↓ Returns: Product Numbers + Descriptions ↓ Credit Request Form (Datalist Dropdown)

Method

  • Triggered by: Form field focus (Product Number field)
  • Query: Searches Business Central for available items
  • Transform: Converts BC item data into datalist format
  • Response: JSON array with matching product numbers and descriptions
  • Used by: Credit Request – Form Handler (validation step)

Mapped Data Points

Business Central → Credit Request Form
BC Item Number → Product Number datalist
BC Item Description → Datalist display text
BC Item Properties → Available for reference

Part 3: Credit Request – Form Handler

Purpose: Process form submissions, create tickets, route to appropriate stage

Processing Steps

1
Webhook Trigger

Receives form submission with all data in JSON format from HubSpot form module

2
Payload Validation
  • Validates account number exists
  • Validates contact information complete
  • Validates product lines (1-10 items, correct structure)
  • Validates Request Type = "Credit" or "Complaint"
  • Calculates Total Quantity across all lines
  • Result: Returns 400 error if validation fails, or proceeds to Step 3
3
Company Lookup
  • Searches HubSpot Companies by ERP Account Number
  • Maps Company ID to workflow storage
  • Result: Returns company details or "Account Not Found" error
4
Contact Upsert
  • Searches/creates HubSpot Contact using email as unique ID
  • Maps to Contact:
    • Email
    • First Name
    • Last Name
    • Phone
  • Stores Contact ID for associations
5
File Uploads (if photos provided)
  • For each photo: Uploads to HubSpot File Manager
  • Location: /credit-requests folder
  • Access: Private
  • File URLs stored for attachment to ticket/items
6
Build Ticket

Subject Line Format: Credit Request: [Account #] - [YYYY-MM-DD]

Maps to Ticket properties:

  • account__ → Account Number
  • company_name → Business Name
  • invoice → Invoice Number
  • credit_summary → Formatted summary of all lines + request type
  • hs_pipeline → "912400389" (Credit Requests pipeline)
  • hs_pipeline_stage → Temporary (will be updated in Step 10)
  • photosdocumentation → All uploaded file URLs
7
Create Ticket & Associations
  • Creates Ticket in HubSpot Tickets object
  • Associates: Ticket ↔ Contact (HubSpot standard association)
  • Associates: Ticket ↔ Company (HubSpot standard association)
  • Stores Ticket ID for item associations
8
Create Items (Loop - 1-10 iterations)

For each product line:

  • Creates Item record (custom object 2-48651243)
  • Item Name Format: [Account #] - [YYYY-MM-DD] - [Product Number]
  • Maps to Item properties:
    • item_name → Formatted name
    • item_no_ → Product Number
    • item_description → Product Description
    • julian_code → Production Code
    • quantity → Quantity
    • request_type → Credit or Complaint
    • complaint_type → Issue Classification
    • line_notes → Notes
    • photosdocumentation → Line-specific photos
    • hs_pipeline → "912368291" (Items pipeline)
    • hs_pipeline_stage → Temporary (will be updated in Step 11)
  • Associates Item ↔ Ticket (custom association)
  • Captures Item IDs for batch update
9
Determine Route (Decision Logic)

Routing Calculation:

  1. Check if ANY item has request_type = "Complaint"
    • YES → Route to CAPA stage
    • NO → Check quantity threshold (Step 2)
  2. Check if Total Quantity ≥ 10
    • YES → Route to Verification stage
    • NO → Route to Credit Decision stage
10
Update Ticket Stage
  • Updates Ticket with determined stage via PATCH request
  • Ticket immediately moves to correct pipeline stage
11
Update Items Stage (Batch)
  • Updates ALL items created in Step 8 with determined stage
  • All items route to same stage as parent ticket
  • Uses batch API for efficiency
12
Success Response
  • Returns JSON response with Ticket ID
  • HTTP Status: 200 OK
  • Used for form confirmation message to customer

Pipeline Stages for Tickets & Items

All tickets and items flow through 4 stages:

Stage 1: Verification
Ticket ID: 1385996039 | Item ID: 1386096010

Triggered when: Credit request with Total Quantity ≥ 10

Team: QA / Supply Chain

Task: Review for accuracy and approval before credit decision

Stage 2: Credit Decision
Ticket ID: 1387983013 | Item ID: 1388087301

Triggered when: Credit request with Total Quantity < 10

Team: Customer Care

Task: Evaluate creditability and approve/deny request

Stage 3: CAPA (Corrective & Preventive Action)
Ticket ID: 1387983014 | Item ID: 1388087302

Triggered when: ANY item marked as "Complaint"

Team: Quality Assurance / Operations

Task: Investigate root cause, document resolution, implement preventive measures

Stage 4: Closed

Triggered: Manual transition when resolution is complete

Indicates: Request fully resolved

Routing Logic Diagram

REQUEST SUBMITTED ↓ [CHECK: Any "Complaint" items?] ├─ YES → CAPA Stage │ (Ticket: 1387983014, Item: 1388087302) │ └─ NO → [CHECK: Total Qty ≥ 10?] ├─ YES → Verification Stage │ (Ticket: 1385996039, Item: 1386096010) │ └─ NO → Credit Decision Stage (Ticket: 1387983013, Item: 1388087301)

Error Handling

Error HTTP Status Message User Action
Validation Failed 400 Specific field error message Fix required fields and resubmit
Account Not Found 404 No account found with that Account # Verify Account # and try again
File Upload Failed Continues Proceeds without photos Resubmit with photos later
HubSpot API Error 500 API error message Support team investigates
